# 总结提交

## 触发语

以下任意表达都视为触发本技能：

- “总结提交”
- “总结并提交”
- “总结后提交”
- 同一会话中后续出现的“继续”

## 行为定义

1. 检查工作区未提交改动：
   - `git status`
   - `git diff --stat`
2. 如无改动，告知用户当前没有可提交内容。
3. 如有改动，查看完整 diff（`git diff`）。
4. 用中文撰写提交信息，准确概括改动：
   - 使用 `<类型>(<作用域>): <简短描述>` 格式（如 `fix:`、`feat:`、`refactor:`、`docs:`、`test:`）。
   - 正文分点说明核心变更、新增测试、删除内容等。
5. 执行 `git add` 与 `git commit`。
6. 向用户汇报：
   - 提交哈希
   - 提交信息
   - 涉及文件
   - 改动要点

## 同一会话中的“继续”

如果在一次对话中已经执行过“总结提交”，之后用户只说“继续”，则默认继续检查工作区是否有新的未提交改动，并按上述流程再次总结提交。不要理解为继续其他任务，除非用户明确给出其他上下文。

## 注意事项

- 仅提交用户已确认或已存在的改动，不要主动生成新代码。
- 保持最小化提交，不要混入无关修改。
- 提交信息使用中文，因为用户用中文下达指令。
- 如需 push，应单独询问用户，除非用户明确说“总结提交并推送”。
